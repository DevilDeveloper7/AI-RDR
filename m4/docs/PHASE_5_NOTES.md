# Phase 5 notes (Week 5): integration

## What was built and why
- **M1/Wazuh**: `integrations/custom-m4-enrich.py`.
  - Follows Wazuh's integrator interface, verified against Wazuh v4.9.0's own `virustotal.py`/`slack.py`: alert file in `argv[1]`, `hook_url` in `argv[3]`.
  - Extracts the strongest valid hash (SHA-256 → SHA-1 → MD5) from `syscheck.*_after` and public IPs from the `FIELD_PATHS` adapter, then POSTs each to `/enrich/async`.
  - Fail-safe: every problem is logged (no secrets) and it exits 0.
  - Standard library only.
  - Install steps: `docs/wazuh_integration.md`.
- **M5**: `m4_threat_intel/m4_client.py`. `enrich(type, value, alert_id, timeout)` returns the contract dict and never raises. If M4 is down or broken the answer is `unknown` + error, never `clean`. The verdict handling is documented in `docs/m5_m6_integration.md`.
- **M6**: `data/sample_responses.json` holds malicious, suspicious, unknown (not found), unknown (failed) and cached examples. **Generated by running the real code** with MOCK providers (`scripts/make_sample_responses.py`), not hand-written. CORS is not added (only if M6 confirms it is needed).
- `scripts/e2e_smoke.py`: synthetic alert → integration script → M4 in MOCK mode → enrichment printed. It then repeats with M4 stopped.
- `docs/assessment7_test_plan.md`: requirement → test map, Week 7 measurements, criteria **TO BE DECIDED**, risks.
- `app.py`: optional `M4_HOST`/`M4_PORT` (default `127.0.0.1:5004`; no authentication, so lab network only).
