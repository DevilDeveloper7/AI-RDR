# backend/irdp/normalize.py imports pipeline/features/event_categories.py
# directly (task 4.1's Correction 2 - reuse the ML engine's real bitmask
# mapping instead of reimplementing it), which itself imports polars.
#
# KNOWN HARDWARE ISSUE, hit twice now on airdr-detect (2026-09-29 and again
# 2026-09-30 - the second time was this exact line silently clobbering the
# already-working fix): airdr-detect's VM CPU (QEMU pc-i440fx/kvm64-class)
# has no AVX/AVX2 flags. Plain `polars` requires AVX2 and crashes on import
# with SIGILL (Illegal instruction), not a catchable Python exception -
# `pip install` reports success anyway. `polars-lts-cpu` ships the same
# importable `polars` module built against SSE4.2 only - pin THIS name, not
# `polars`, or a future `pip install -r requirements.txt` will overwrite a
# working install with the AVX2 build again.

# 10/80 tests to fail with ModuleNotFoundError on the one host that doesn't
# happen to have it already installed for an unrelated reason. Verified
# clean on airdr-detect's no-AVX2 CPU (no equivalent -lts-cpu variant
